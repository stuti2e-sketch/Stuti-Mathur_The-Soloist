## 1. Project title
**Neurodivergent Learning & Sentiment Dashboard: Inclusive Workforce Learning Analytics**

## 2. Problem statement
Neurodivergent employees—including people with ADHD, autism, dyslexia and dyscalculia—may experience different learning needs and barriers in standard corporate training. Generic completion-only reporting can miss disengagement, inaccessible learning formats, and unmet accommodation needs. Managers need an interpretable, privacy-conscious overview that supports timely, voluntary and supportive follow-up rather than punitive profiling.

## 3. Healthcare use case
The concept targets learning-and-development teams in healthcare organizations, pharmaceutical firms, hospitals and health-technology workplaces. A training manager could review cohort-level completion, engagement, sentiment and support indicators; identify potential accessibility issues; and offer appropriate accommodations. This is **not** a diagnostic, clinical decision-support or employee-selection tool. No medical diagnosis or employment decision should be inferred from the dashboard.

## 5. Technical stack
- Python 3 (standard library: `tkinter`, `time`; no third-party packages)
- Original project reference: Stanford Code in Place `graphics.Canvas` interface (`from graphics import Canvas`), which requires that course-specific runtime.
- This repository includes a **standalone, runnable Tkinter adaptation** (`dashboard.py`) to make the concept independently reviewable. The adaptation retains the same 800 × 600 visual structure, charts and keyboard refresh simulation.
- Data: static synthetic constants embedded in source. There is no database, API, network connection or production HR integration.

## 6. AI/ML framework — Python learning-support tracking prototype
**Framework:** Python + scikit-learn (`RandomForestClassifier`) + NumPy, alongside the Tkinter dashboard. The separately runnable `ml_framework.py` demonstrates an **implemented machine-learning pipeline** using entirely synthetic data.

**Purpose:** Estimate a *synthetic follow-up priority score* to help illustrate how learning teams might offer voluntary support. It is **not a measure of disability, ability, job performance or clinical risk**.

**Input features:** completion percentage, days since last activity, engagement, confidence, accommodation adequacy, stress and change in session duration. **No diagnosis or neurotype is used as a model feature.**

**Pipeline:** generate 1,500 fictional learner records with a fixed random seed → create simulated support-follow-up labels from an explicit artificial rule → stratified 75/25 train/test split → fit a Random Forest → report holdout ROC-AUC and classification metrics on synthetic data → score an example fictional learner → suggest a *human-reviewed* supportive check-in. The test set is held out from fitting, but because labels are generated by an artificial rule, these metrics do **not** demonstrate real-world validity or effectiveness.

**Run:** `pip install -r requirements.txt` followed by `python ml_framework.py`. The Tkinter UI (`dashboard.py`) remains a separate visual prototype and **does not yet invoke the ML model**. Production integration would require lawful consent, independent real-world validation, privacy safeguards, accessibility review, and human oversight.

## 7. Architecture
**Dashboard path:** `Synthetic example metrics → Python data structures → Tkinter Canvas → visual refresh`.

**AI/ML demonstration path:** `Synthetic training records → feature matrix → artificial follow-up labels → train/test split → scikit-learn Random Forest → synthetic holdout evaluation → supportive check-in suggestion`.

These are **separate runnable modules**, not an integrated live tracking system. The supplied [`architecture.pdf`](architecture.pdf) illustrates the original dashboard architecture; the ML pipeline is documented here and in [`ml_framework.py`](ml_framework.py).

## 8. Run instructions
1. Install Python 3 with Tkinter support (usually included on Windows/macOS; some Linux distributions require `python3-tk`).
2. Download or clone this repository.
3. Run `python dashboard.py`.
4. Press **R** to replay a brief refresh animation; press **Esc** to exit.

The refresh is a **visual simulation only**; no new data is fetched or generated. A desktop graphical environment is required.

## 11. Privacy, ethics and limitations
- All shown records are fabricated demonstration examples; names are fictional.
- Never publish actual employee diagnoses, disability information, sentiment or individual learning profiles without appropriate consent, safeguards and lawful processing.
- The prototype is not live, not connected to HR systems, and neither its ML predictions nor its simulated evaluation metrics have been validated in a clinical or real workplace environment.
- Attention signals should trigger supportive human review, not automatic disciplinary action.
- For real deployment: role-based access, anonymisation/aggregation, data minimisation, accessible design, audit logs and stakeholder review are required.
